# mac_sync

Обмен файлами между Mac без Wi-Fi, USB и OBEX. Сейчас здесь только
диагностический прототип CP001: передача файлов ещё не реализована.

Основной код — Python. Нативные системные API вызываются через PyObjC.
Собственного C/Objective-C кода пока нет.

## Два компьютера

| Метка | Компьютер | Кто проверяет |
|---|---|---|
| `local-arm64` | Текущий Mac, ARM64, наблюдаемая macOS 27.2.1 | Агент |
| `peer-intel` | MacBook Pro 2019, x86_64, macOS Tahoe 26.7.1 со слов пользователя | Пользователь |

Окружение создаётся отдельно на каждом Mac. `.venv` между компьютерами не копировать.
Пока распространяем исходники, а не бинарную сборку.

Продолжение работы: [CHECKPOINT.md](CHECKPOINT.md).
Проверка второго Mac: [docs/PEER_INTEL.md](docs/PEER_INTEL.md).
Проверка текущего Mac: [docs/LOCAL_ARM64.md](docs/LOCAL_ARM64.md).

## Решение по транспорту ещё не принято

Первый кандидат — RFCOMM без OBEX. Если он недоступен, проверяем BLE GATT,
затем при необходимости BLE L2CAP. Все варианты используют службы macOS.
Наличие класса API и состояние powered_on не доказывают возможность передачи.
Для выбора нужен отдельный двусторонний тест.

## Окружение

Нужен нативный Python 3.11 или новее; первоначальная цель — проверить 3.14.
Совместимость зависимостей с Intel и обеими ОС пока не подтверждена.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Без зависимостей доступен отчёт об окружении; Bluetooth-проверка требует PyObjC.
Сырые JSON-отчёты игнорируются Git. Скрипт не собирает имена устройств,
адреса, список соседних устройств или содержимое файлов.
